Projekt

Wie capulus-core aufgebaut ist

Ein Ansible-Lauf verwandelt einen einzelnen Server in ein produktionsreifes GitOps-Homelab: gehärtetes Ubuntu, k3s, ArgoCD und Tailscale arbeiten zusammen – reproduzierbar, dokumentiert und mit null offenen Ports nach außen.

Infrastruktur

Ein gehärteter Server, komplett per Ansible

Den Anfang macht ein einzelnes Ansible-Playbook: Es installiert ein gehärtetes Ubuntu Server 26.04 LTS mit UFW-Firewall, richtet k3s als schlankes Kubernetes ein – inklusive Traefik als Ingress und CoreDNS – und legt damit das Fundament für alles Weitere. Kein manuelles Geklicke, keine Doku, die nach zwei Monaten nicht mehr stimmt: Jeder Schritt steht im Playbook.

  • Ubuntu Server 26.04 LTS, gehärtet, UFW-Firewall
  • k3s inkl. Traefik v2 & CoreDNS
  • Ansible ≥2.14, idempotent, Secrets per Vault verschlüsselt
  • Split-DNS via dnsmasq + Pi-hole für *.homeserver

GitOps-Workflow

Neue Anwendung? Einfach nach Git pushen.

ArgoCD überwacht das argocd/apps/-Verzeichnis dieses Repos und synchronisiert jede Änderung automatisch in den Cluster – ganz ohne kubectl apply von Hand. Eine neue App hinzuzufügen heißt: Ordner anlegen, Kubernetes-YAML oder Helm-Chart hineinlegen, committen, pushen. Nach spätestens drei Minuten läuft sie in ihrem eigenen Namespace.

  • Deklarativ: Cluster-Zustand = Zustand des Git-Repos
  • ArgoCD ApplicationSets erkennen neue Ordner automatisch
  • Nur lesender Zugriff: ArgoCD kann das Repo nicht verändern
  • Jede App bekommt ihren eigenen Namespace
Workflow in der Doku
$ mkdir -p argocd/apps/mein-service
$ git add argocd/apps/mein-service
$ git commit -m "add mein-service"
$ git push
✓ ArgoCD sync in ~3 Min

Sicherheit & Netzwerk

Kein einziger offener Port

Zugriff gibt es ausschließlich über mein eigenes Tailscale-Tailnet oder gezielt über einen Cloudflare Tunnel – niemals über direkt aus dem Internet erreichbare Ports.

Zero Open Ports

UFW erlaubt nur SSH, HTTP/S, die k3s-API, Flannel und Tailscale – der Rest bleibt zu.

Verschlüsselte Secrets

Ansible Vault für die Provisionierung, Sealed Secrets für alles, was danach in Git landet.

Automatische Updates

APT-Security-Patches, k3s, Helm-Charts und alle Apps aktualisieren sich selbstständig – inklusive Reboot bei Bedarf.

Hardware

Worauf das Ganze läuft

capulus-core selbst ist für einen einzelnen Node ausgelegt – bei mir ist mit der Zeit ein kleiner Drei-Node-Cluster daraus geworden. Offizielle Mindestanforderung laut Projekt: 4 GB RAM, 20 GB Speicher.

Lastverteilung in Aktion

Im Ruhebetrieb reicht der Homeserver für alle Standard-Workloads. Steigt die Last, fährt er worker-0 und worker-1 automatisch hoch und verteilt Pods über den k3s-Scheduler neu – sinkt sie wieder, fahren beide zurück in den Standby.
